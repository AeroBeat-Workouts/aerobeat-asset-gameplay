## Rebuild/validation

Run on a host with Blender **4.0.2**, in a clean *new* candidate root (generation refuses populated roots):

```bash
blender --background --factory-startup --python tools/generate_knee_candidates.py -- --output-root /tmp/knee-art-build-a
python3 tools/validate_knee_candidates.py --candidate-root /tmp/knee-art-build-a --smoke
```

`--smoke` checks all three editable scenes and exported GLBs in Blender, as well as manifest-bound files, normal attributes, analytic materials and tint metadata. Repeat in `/tmp/knee-art-build-b` to verify valid outputs, but **do not claim bitwise reproducibility yet**. Two clean Blender 4.0.2 runs produced different `.blend`, GLB geometry-buffer and PNG bytes (all 3 GLBs and 16 PNGs), even with a fixed Cycles seed; the target open-prong GLB also varied in buffer lengths. The per-build manifest binds the generated bytes and strict structural checks pass, but a deterministic final export pipeline remains necessary **after** the two human approvals and before any immutable release. The retained evidence came from the current fixed-seed, texture-free generator; its stored SHA-256 inventory is self-consistent. Regenerate only into a **new isolated root**, not over these review files. The manifest is explicitly **provisional**, not a canonical v1 release manifest. Texture/images/extensions are absent from the GLBs; preview lights/camera are stored in editable scenes but excluded from GLB exports.
